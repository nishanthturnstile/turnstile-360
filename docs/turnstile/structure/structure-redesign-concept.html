Review findings and implementation sequence

Design review · 14 November 2026. Live Structure inspected at 1280 × 800 and 390 × 844. Chart, outline, rename, creation, move and deletion subforms inspected without submitting business mutations. This concept is a proposal, not a deployed application change.

What should change

Before After Why
Outline is the default. Chart is the same nested list rearranged with CSS. Chart first on desktop; connected cards, pan, zoom, Fit, branch focus and a dense outline alternative. Relationships become immediately legible; large hierarchies remain navigable.
Large page header, repeated hierarchy heading and pagination consume the viewport. One compact header and toolbar above a bounded canvas. More working space without extra page scrolling.
Manage opens rename immediately and narrows/reflows the chart; the panel stacks above it on phones. Selection opens an overview overlay. Explicit Add department, Rename and Move actions open one task. Full-screen task sheet on phones. Browsing stays separate from editing; the selected context and camera survive.
Parent/type selectors offer invalid combinations, self/descendant moves and deletion of known non-leaves. Infer legal types and known parent relationships, preserve the full destination path and show unavailable actions with reasons. Confirm availability server-side. Explain predictable restrictions before a rejected submission.
Switching editing actions or using Cancel can discard typed unit input. One dirty-draft guard covers action changes, Close, Cancel and navigation. Read-only browsing does not mark the page dirty; pending and uncertain commands remain guarded. Protect work consistently and avoid unnecessary discard prompts.
One page contains at most 100 authorized units with contextual ancestors. Assemble authorized pages only when organization revision, access revision and scope match. Show loading completeness; retry from a clean revision on conflict. A partial chart must never imply a complete organization or disclose hidden branches.
Move review shows aggregate counts but little visual context. Before/after paths, destination preview, subtree and server-reported affected member/invitation counts. Make inherited-access effects understandable before confirmation.

Implement in this order

  1. Scoped data and state. Define a normalized presentation model that separates actionable units from ancestor context. Aggregate cursor pages at consistent revisions within the current 500-unit / 8-level limit. Reuse subject/access-scoped React Query caching and invalidation; never fetch onboarding's unrestricted snapshot. Cancel obsolete loads; keep selection/camera on background refresh.
  2. Chart workspace. Reuse the tested layout/camera helpers behind a scoped adapter. Support a forest for disjoint visible branches, clear connectors, readable cards, branch collapse, Fit and reset. Preserve canonical order; no persisted coordinates. Show Chart/Outline as a visible segmented control. Use one compact header and internally bounded scrolling.
  3. Find and navigate. Search full authorized results, retain ancestry, reveal a selected match, display breadcrumbs and offer Focus branch / Back to organization. Keep branch collapse and selection synchronized across views. Add a collapsible navigator only for larger desktop workspaces; no permanent extra column.
  4. Details and creation. Open a read-only overview first. Expose explicit task actions and a contextual + shortcut. Infer site-under-organization and department-under-legal-parent choices. Preserve drafts across collapse, refresh and rejected navigation. Guard action changes, Close and Cancel consistently; mark only real edits dirty. Root name links to General settings only for authorized managers.
  5. Rename, move and delete. Use one guarded task sheet with the existing review/command state machine. Explain restrictions on known invalid destinations and non-leaf removal. Final server authorization remains decisive. Show old/new paths and real move-impact counts; preserve uncertain command readback and command keys. Add drag-to-move only after the click/keyboard path passes the same review flow.
  6. Access context. Add a permission-gated shortcut to Members filtered by coverage. Label it “Members with access” rather than employee/headcount. Reuse the existing unit-filtered Members directory and per-member access inspection for drilldowns. Efficient unit-wide assignment summaries, authoritative deletion blockers and structure-specific activity need explicit server projections; the present unit-detail and People audit APIs do not provide those summaries. Label suspended assignments separately from active coverage. Negotiate additive contracts so older strict clients remain compatible.
  7. Responsive, recovery and performance validation. Test root-only, empty scoped access, duplicate/long names, disjoint scopes, 100/101/500 units, 8 levels, revision changes during pagination, grant loss and cancelled reads, stale edits, lost acknowledgements, keyboard/touch and reduced motion. Test 1440/1280 desktop, tablet and 390/320 phone layouts. Show node/loading errors locally; retain existing rows during background refresh and never replay writes automatically.
  8. Release. Run all four workspace gates plus actual HTTPS/PostgreSQL/browser journeys, update gallery/docs, build the signed source-matched release, use the existing supported cutover, and compare retained units/access before and after. No implementation or deployment is claimed by this proposal.

Reference patterns

SAP Company Structure Overview informs branch navigation and direct/substructure detail. SAP Network Graph informs collapse and zoom-to-fit. Google Resource Manager explains how moving hierarchy nodes changes inherited policies. Microsoft Entra administrative units informs explicit delegated scope; its non-nested unit model is not our hierarchy model. These are interaction references, not a recommendation to change Turnstile's domain rules.

Implementation boundary: keep scoped reads, permissions and command ownership in the completed-workspace Structure feature. Extract a presentation adapter for the existing layout/camera helpers, with ancestor-only cards explicitly non-actionable; do not reuse onboarding's unrestricted editor or make every rendered card manageable. Keep the configured shadcn/Base UI components, Hugeicons, fonts and semantic tokens. Extend the development gallery with scoped, partial-loading, draft, conflict, empty, deep and narrow examples. This isolated HTML uses sample data to demonstrate the proposal and does not add a new application UI framework or interaction dependency.

Priorities: first deliver scoped chart/navigation and form corrections (steps 1–5); then scoped access insights (step 6). Image/CSV export, minimap, saved views, hierarchy imports, multiple hierarchies, new unit types and employee reporting lines are separately scoped follow-ups, not necessary for the first redesign. Avoid implying that module access assignments are employment records.
