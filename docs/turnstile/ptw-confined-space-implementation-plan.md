# Confined-space Permit to Work implementation plan

**Delivery decision.** Confined Space is the first complete PTW workflow. Demonstrate a named team preparing, authorizing, entering, stopping, exiting and handing back one space. PTW and Learning Management (LMS) are separate Individual modules. The PTW team can begin immediately with synthetic competency responses. Operational entry requires a qualified authoritative provider and the site's published procedure.

This plan supersedes the Hot Work pilot order in the [discovery plan](ptw-workflow-plan.md). Use the [policy decisions](ptw-policy-decisions.md) for site setup, [industry analysis](ptw-industry-research.md) for differences between procedures, [module build audit](ptw-build-readiness.md) for packaging work and [accepted architecture](../../architecture.md#turnstile-application-architecture) for product boundaries.

### Selected builds and the LMS dependency

Use a qualification-only source/catalogue release for CS-01 without a claimed LMS dependency. Keep fixture injection in a separate test composition. Inspect the exact candidate customer image separately and prove that it excludes test assets and blocks operational commands with the provider absent. Shadow exercises using synthetic credentials run only on the test composition.

When LMS has a published identity and implementation, publish a **new** reviewed source/catalogue release declaring LMS as required for PTW. Required dependencies belong to the catalogue version. A per-site switch cannot alter them. Test that resolving operational PTW selection includes LMS, that a mismatched signed assignment/profile cannot activate, and that a customer can still select LMS without PTW. Keep the earlier qualification release out of operational distribution.

CS-01 owns scoped discovery in place of the current company-only landing permission, action grants, nested-route/deep-link compatibility, selected migration journals, and private dependency/asset exclusion. Use a shared portable contract and selected server composition with no cross-feature private imports. Include negative tests with an older web client and a fresh Core installation.

### Competency contract for both teams

Propose a batch read at the backend integration boundary. Define portable request, response, errors and examples in the public contracts layer. Bind an authenticated server-side adapter at composition time. A same-product provider can implement that interface inside the selected Turnstile backend. A separately deployed provider uses authenticated HTTP. Agree transport during LMS implementation without changing PTW commands or screens.

- **Request:** contract version, installation/application context derived from the authenticated caller, site ID, evaluation instant, proposed start/end and a list of person IDs with requested competency IDs. PTW resolves IDs from published site policy for the assigned roles. No course names, pass marks, hardcoded people or vendor identifiers in permit logic.
- **Response:** source and revision, evaluated time, per-person/per-competency outcome and reason, supporting credential reference, issue/valid-from/valid-until dates where applicable, verification state and revocation time if present. Distinguish current, missing, expired, revoked, unverified and unknown. Include an explicit response for each requested pair. A missing row, foreign identity, unsupported version, malformed interval or partial response leaves that requirement outstanding. Medical fitness, contractor approval, role conflicts and field readiness have their own sources.
- **Decision:** PTW compares verified evidence with the required work interval, site policy, permitted sources and freshness window. Passing training makes a person eligible for the relevant role subject to the remaining checks. Save minimal evidence references, facts, provenance, policy revision, actor, time and decision. Keep sensitive course transcripts and medical records with their owners.
- **Refresh:** preview gaps at selection, check again on crew or window change, authorization, start, entry and restart. A provider timeout enables draft work and preserves historical results. Mandatory checks block a new authorization when evidence is missing or stale. On revocation or expiry during active work, identify affected roles and operations, stop or evacuate per approved procedure and alert the supervisor. Use event ID, person and competency IDs, source revision, effective time and change kind. Deduplicate events, reject older revisions and repair missed changes by periodic reconciliation and scheduled expiry checks. At each decision reject stale provider responses and evidence superseded by a known newer revision. Test response/revocation races and expiry in CS-01, CS-04 and CS-05.
- **Temporary adapter:** a developer or tester sets up named scenarios in an isolated test harness using synthetic organization members, competency mappings and relative validity windows. Scenarios include a qualified team, wrong person, partial result, mid-shift expiry, revocation and provider outage. Feed the same contract into the real eligibility evaluator. If inline editing helps a demo, edit the fixture in the harness and rerun the lookup. Keep test provenance visible throughout. Exclude the harness, fixture source, edit endpoint and adapter from customer images. Bind provenance to the authenticated provider and server-selected adapter. A self-declared source label cannot establish trust. The customer server rejects simulated evidence and unconfigured providers for operational commands.
- **Cutover:** run the same conformance suite against the real LMS adapter. Verify a course assignment alone leaves the worker ineligible, accepted completion grants the mapped competency, and expiry or withdrawal removes it. Exercise lost events, stale revisions and cross-site access. Require a new eligibility check with the authoritative source on every synthetic-to-real transition. Use separate synthetic and operational records, and rehearse rollback to blocked issuance if the LMS becomes unavailable.

Example conformance case: the entrant has valid entry training, the tester's credential expires before shift end, and the rescue responder's identity has no verified match. The requester sees two named gaps and can replace the affected workers or revise the window. The reviewer sees the same outcomes and evidence basis. A complete course for the entrant cannot satisfy the tester's requirement.

### First shared contract fixture

| Worker A / competency required for entrant                   | Verified credential valid until 16:00, current revision                     | Training requirement satisfied for this window. Other entry controls still apply.                                |
| Worker B / competency required for tester                    | Verified credential valid until 12:00                                       | Show the gap from 12:00 and block authorization for this crew and window.                                        |

Preparation access in the pilot is limited to work outside the space. Crossing the entry plane requires entry authority. Verify acceptable samples at the prescribed locations, ongoing ventilation where required and currently available detection at admission. Elapsed ventilation time alone cannot satisfy those checks. Persist ventilation start, duration, completion, interruption and verifier against the operation. Invalidate a cycle when a prerequisite fails. During service or entitlement loss, physical egress and the site emergency procedure remain available immediately. Exercise digital exit and SOS while a permit is suspended and its module remains authorized. Exercise the independent site fallback when the platform itself denies PTW access.

### Cross-role acceptance scenarios

- Identify the site-authorized checklist approver separately from the permit issuer. For Critical work apply the published independence rules to reviewer, issuer and performing team. Exercise wrong signer, wrong checklist revision, too few workers and an unqualified watcher via direct API and field UI.
- Admit through two different openings to one physical space and enforce the same occupancy limit. Prevent a worker already inside one space from acquiring a simultaneous incompatible admission elsewhere. Make current multi-point test results visible to entrants and maintain ventilation and monitoring for the required duration.
- Any worker can report a stop and evacuate immediately. The field record distinguishes delivery of a warning from acknowledgement by the attendant and physical accounting for each person.
- Operations may accept handback with a shared isolation still under named custody. Preserve its reference, owner and restrictions. Only the authorized isolation authority can release after every dependent obligation clears and formal restoration checks pass.

## State and integration rules

Keep the permit revision, checklist revision, entry operation, ventilation cycle and individual admission identifiable separately. A permit may be approved and waiting to start while its linked checklist is still outstanding. Display next actor and blocker on both records. Only an open admission increases occupancy. An SOS or suspension preserves the roster. An authorization ending by time cannot erase obligations to account for people, secure the space or complete handback.

Use expected revisions and retry keys on consequential commands. Persist the decision, evidence snapshot and pending deliveries together. Replayed events cannot restore invalid approvals. Serialize occupancy, shared-isolation release and conflict decisions against their actual shared resource. Field and register actions use the same authorization checks. Run role-denial, site-isolation and entitlement tests against both direct API and web routes.

Use typed references to external JSA, risk, isolation, equipment and rescue records. Where the owning module is unavailable, a site may accept verified external records under its published policy, including per-source isolation verification. Record verifier, source revision and withdrawal/recheck process. A synthetic training response is confined to development. Site publication of manual atmosphere readings requires a qualified instrument, tester, traceable readings and a procedure that accepts that method. Sites requiring continuous monitoring or hardware interlocks must qualify those integrations before operational entry.

Stage peer deliveries independently. PTW must expose and reconcile its own required tasks, alerts, roster and audit even while a shared dashboard or Action Tracker integration is pending. Document publication uses DMS authorization and versioned evidence. Preserve read access for eligible auditors under retention. For planned local cutover, drain entrants, emergencies, work handbacks and isolation obligations before removing the module. Central suspension, expiry, transitive LMS loss or an unplanned outage can fence ordinary PTW routes immediately. Provide a site-controlled roster and accountable attendant at the opening with independent communications and a current paper or approved offline muster record before entry. Continue physical evacuation and accounting there during restriction. Reconcile signed observations after authorized restoration. Test sudden central restriction with people inside and an omitted-module build. Any digital restricted-mode write requires separately qualified platform authority.

## Release gates and decisions

1. **Ready to implement.** Begin CS-01 with a consumer contract and synthetic conformance data. Begin CS-02 once identifiers, read scope and contract ownership agree. LMS course design, course creation and assignment screens, other permit types, AI assistance, native mobile and physical actuation are separate work.
2. **Ready for shadow use.** Pass CS-01 through CS-06 in a clearly identified non-operational installation with synthetic evidence. Run the repository's check, build, unit and integration gates and selected-image tests. Rehearse browser/API actions through configured ingress, including lost acknowledgements, retries after a state change, two-device races and stale evidence. Record actual runtime results separately from static checks.
3. **Ready for operational use.** Complete CS-07 with real training evidence and a signed site procedure. Confirm jurisdiction, site and accountable authority, role compatibility and cover, monitoring thresholds/units/boundaries and stale-data response, emergency contacts/fallback, recovery or cancellation rules and handback responsibilities. Verify the real customer profile includes the required LMS capability. Test fresh install, omitted build, retained upgrade, restricted mode and rollback. Only then enable live authorization for that site.

The first implementation decision is to freeze the competency contract with the LMS owner. The first customer decision is which site's approved confined-space procedure to use for qualification. Engineering can start with the development provider while that site decision is pending.
